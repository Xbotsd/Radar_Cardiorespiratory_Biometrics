# 使用说明

这个仓库在算什么、怎么装、怎么跑、结果怎么读、哪里容易误读。

---

## 一、它在回答什么问题

不是"我的分类器有多准"，而是：

> **一个雷达心肺特征给出的高准确率里，有多少是"评估协议"造出来的，有多少是生理本身？**

具体拆成三个实验：

| 实验 | 通俗问法 | 论文结论 |
|---|---|---|
| 闭集识别（30 只狗） | 同一批狗，换时间还能认出个体吗？ | 窗口级 54.4%，按时间切块 46.1%，隔 25 分钟只剩 16.3% |
| 开集验证 | 没见过的狗，会被当成"陌生人"拒绝吗？ | 固定划分 89.6%，随机重划 20 次只剩 20% 左右，AUROC≈0.52（等于瞎猜） |
| 跨物种（狗 vs 人） | 雷达能区分人和狗吗？ | 86.2%，但两批人分别用 60 GHz 与 120 GHz 雷达记录时，同一套流程能分到 93.8% |

一句话：**在这三份公开数据上，"物种可分性"没有超过"硬件可分性"**。所以"雷达能分辨人和动物"这句话，目前没有公开数据支撑。

## 二、看懂结果的五个概念

### 2.1 窗口重叠泄漏（P0）

一段 180 秒的记录切成很多 15 秒窗口，相邻窗口有 50% 重叠。如果把这些窗口**随机**分到训练集和测试集，同一段录音的窗口会同时出现在两边——模型记住的是"这段录音的噪声底"，不是"这个人"。

这就是 P0，也是绝大多数文献报的数。它是**上限**，不是泛化能力。

### 2.2 时间块划分 + 保护间隔（P1）

按每个受试者的时间轴切：前 60% 窗口训练，后 40% 测试，中间丢掉 5 个窗口（75 秒）作为保护间隔，保证测试窗口和训练窗口不共享采样点。

泄漏被切断之后，30 只狗从 54.4% 掉到 46.1%。注意：保护间隔从 0 扫到 10 个窗口，结果几乎不动（47.4% → 46.9%），说明**掉下来的 7 个点不是相邻窗口共享样本造成的**，而是"同一次录音的稳定噪声特征"被当成了身份。

### 2.3 25 分钟预测视界（P2）

训练用前 3 分钟，测试用 25 分钟之后的窗口。同一只狗、同一次实验、同一台雷达，只是隔了 22 分钟。

结果 16.3%。这是"跨时段识别"的真实水平——比随机猜（3.3%）高，但离可用还很远。

### 2.4 阴性对照（NC1 / NC2 / NC3）

这是全文最关键的设计。**只有阳性结果、没有阴性对照的实验，无法判断分类器学到的是什么。**

| 对照 | 换掉了什么 | 保持了什麼 | 平衡准确率 |
|---|---|---|---|
| NC1 跨平台对照 | 雷达 + 受试者 + 协议（110 人 60 GHz vs 24 人 120 GHz） | 物种（都是人） | 93.8% |
| NC2 状态对照 | 麻醉 vs 清醒（两组不同的狗） | 物种 + 雷达 | 83.5% |
| NC3 生理对照 | 静息 vs 运动后（同一批 110 人） | 物种 + 雷达 + 受试者 | 67.0% |
| 主实验 | 物种（狗 vs 人） | —— | 86.2% |

**换一整套采集条件（雷达、受试者、协议同时换）比换物种还容易分。** 这就是结论的实质；NC1 因此只能界定"采集条件"的上界，不能单独归因于硬件。

### 2.5 采样率匹配（rate-matched control）

把狗的 50 Hz 数据抽取到 10 Hz（和 60 GHz 人类数据同一帧率），再提特征：

- 5 个"依赖网格"的特征（谱质心、谱熵、LF/HF 比等）：97.6% → 82.9%，掉 14.7 个点
- 16 个"不依赖网格"的特征：86.2% → 86.4%，掉 0.2 个点

含义：老特征集里很大一部分"判别力"其实是在测采样率。选特征时先做一次抽取对照，成本只有一遍数据。

## 三、安装

```bash
git clone https://github.com/Xbotsd/Radar_Cardiorespiratory_Biometrics.git
cd Radar_Cardiorespiratory_Biometrics

python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # Linux / macOS

pip install -e .
pytest -q                       # 应显示 39 passed
```

依赖只有 `numpy`、`scipy`、`pandas`、`scikit-learn`、`matplotlib`、`openpyxl`。

数据不在仓库里，需要按 `docs/DATA.md` 的目录结构准备，然后：

```powershell
$env:RCB_DATA_ROOT = "C:\path\to\Biometric_Project"     # Windows
export RCB_DATA_ROOT=/path/to/Biometric_Project         # Linux / macOS
```

不设也可以，默认读 `~/Desktop/Biometric_Project`。

## 四、跑哪几个脚本

```bash
python scripts/run_all.py            # 全流程，约 15 分钟（不含首次缓存）
python scripts/run_all.py --figures  # 只重画图和数字表
```

或者单独跑：

| 脚本 | 作用 | 耗时 | 需要原始数据 |
|---|---|---|---|
| `00_cache_dogs.py` | 狗数据 CSV → float32 缓存（约 3.5 GB） | ~2 min | 是 |
| `01_extract_features.py` | 所有窗口级特征表 | ~6 min | 是 |
| `02_vital_signs.py` | 心率/呼吸率结果 + 消融 | ~4 min | 是 |
| `03_identification.py` | 闭集三种协议 + 开集重复划分 | ~3 min | 是 |
| `04_cross_species.py` | 跨物种 + 三个阴性对照 + 迁移 + 置换检验 | ~2 min | 是 |
| `05_rate_matched_age.py` | 采样率匹配对照 + 年龄回归 | ~2 min | 是 |
| `06 make_figures.py` | 七张论文图 | ~1 min | 否 |
| `07_number_table.py` | 生成 `docs/NUMBERS.md` | 秒级 | 否 |

**只有特征表、没有原始数据时**：`02`–`05` 仍然可以跑，因为它们读 `results/features/*.csv`。这是刻意的设计——审稿人不需要下载 3.5 GB 原始数据也能验证统计结论。

## 六、常见问题

**开集怎么从 89.6% 掉到 20%？**
固定的那个划分里，"已知"恰好是 10 只麻醉狗，"未知"是其余 20 只。这个划分对马氏距离特别友好。把 30 只狗随机分成 10 已知 / 20 未知，重复 20 次，AUROC 就是 0.52——阈值在标定集上看着很好，换一批未知就失效。论文报的是 20 次划分的分布，不是那一次幸运划分。

**跨物种 86.2% 已经不低了，为什么还说是阴性结果？**
因为同物种、换硬件的对照是 93.8%。如果分类器学到的是"物种"，狗的分数应该明显高于"人 vs 人"；实际相反。再加上迁移实验：在"狗 + 60 GHz 人"上训练，拿去判 120 GHz 的人，96.3% 判成人；反过来在"狗 + 120 GHz 人"上训练，判 60 GHz 的人只有 24.1% 判成人——人的标签跟着平台走。

**年龄回归 R² 是负的，是不是代码错了？**
不是。随机森林 R² = −0.15，岭回归 −0.04，常数预测器（直接输出均值）−0.03。也就是说，两个模型都没有超过"猜平均值"。在 10 Hz 帧率、20 秒窗口下，HRV 类特征根本估不准（RMSSD 需要数分钟平稳记录），这是数据的分辨率上限，论文把它作为阴性结果如实报告。

**为什么狗的数据不做相位解缠？**
这份 7.3 GHz 超宽带数据发布的是实值混频采样，不是复距离像。呼吸和心跳只能在频域分离，没有相位可解。仓库里对这份数据直接做滤波 + 谱峰，不做相位解缠。

**能不能只跑 `04_cross_species.py` 复现 86.2%？**
可以，但需要先有 `01_extract_features.py` 产出的特征表（已提交在 `results/features/`）。直接跑 `04` 会读这些 CSV。

**为什么测试里有一条 `species <= control` 的断言？**
那条断言锁住的是论文的中心结论。如果哪天数据或代码让"物种可分性"超过"硬件对照"，论文应该重写，而不是放宽测试。这是有意的设计。
